# 病情轻重｜V-next 条件证据审查分支（保留 V3.9.1）

记录：2026-10-23。状态：**独立审阅候选，不是已经替换的正式疾病诊断模板，更不是 iOS App 上已经启用的新断词**。

## 为什么要改

现有 V3.9.1 由 V3.9 及先前 V3.5/V3.7 推理继承「病吉/病凶」二元主判；原书 81 种有序天地干来源、42 疾病补充、17 复合规则很多是书面格局名称或关键词识别，`source_conditions_present` 只是关键词存在与否，并不是全部原书条件的机器证明。可能造成「天地干命中」被错误上升为「吉凶格已成立」；同一入墓与十二长生临墓、同一盘的患者宫与病宫角色重合又会反复出现；遇到强反证没有明确暂不判断路径。已认可的 V3.9.1 必须原样保留。

## 本轮实现（已写入 GitHub main）

- `src/wengua/health_severity_vnext_review.py`：V3.9.1 和原 V3.9 底座读取并且不更改；按人物取用可信度、患者→病宫、病宫→天芮、医药反证、旬空刑墓等重新审查主判，允许 favorable / adverse / conflicted / unresolved 四种状态。面向用户对应「传统偏吉/偏不利/强证据相持/吉凶暂不能定」；**绝无分值概率**。
- 有序天地干：真实匹配的是 9 个星携干配地盘干，不是「同时触发 81 个格局」。`review_ordered_pairs` 将来自 `ordered_stem_pairs.json` 的条件标志分类；**关键词为空也不代表全部条件已满足**。当前没有机器可执行、逐项证明的作者原书完整谓词，不自动让名称或含「吉」「凶」字样影响主判。42 条疾病名称/来源别名不得成为第 2 条独立证据；保持内部源行/hash，不输出 UI。
- 人物：仅书源足够明确的 `source_case_specific` 等角色可进入强判；同辈月干/晚辈类推/闻讯事件特殊身份为条件候选，缺条件时不强断。不改变用户输入及 `health_dynamic_v21.bind_patient` 的原始对照。
- `dedup_lifecycle_facts`：同一实际宫位、相同天干、同一地支的长生/墓只存 1 个标准事实 ID，关联多个角色时角色集合增加，不将「临墓」重复作为另一个「入墓」凶证，天盘与地盘仍应由九宫事实引擎区分。
- 推理目前只有核定“双重制病且患者无空/刑墓”可直接给传统有利候选；不利必须具备「病宫克患者且病宫生扶天芮」、「患者生病宫再生天芮」等两独立关系；不利链遇医药独立制病为冲突；没有这些条件则 **unresolved**，不沿用旧版强制二元。此优先级只是审阅候选，不能据此自称比旧断词正确或具医学准确性。
- 重新组织**六段客户阅读候选**：主判断 → 患者病宫（主证、生克、天地干十二长生）→ 医药和相反事实 → 格局限制及未核作者条件 → 时干、伏吟反吟、旬空、驿马及尚未触发的应期 → 值符值使和辅助。文字全部由核定的原盘结构及事实重组，**不直接拼接旧版未完整验证的吉凶句子**。
- `src/wengua/health_text_pipeline_vnext_review.py` 增加 **单独的** `auto_cast_health_review_text`；旧 `src/wengua/health_text_pipeline.py` 的公开 `auto_cast_health_v39_text` 完全不动。iOS SwiftUI 当前不指向这条预览入口。
- `tests/test_health_vnext_conditional_review.py` 测未核人物、书中关键词不足、入墓去重、强反证冲突、无根据不出二元，以及4张原本已封存盘的旧 V3.9.1 原文 SHA256 **逐字不变**。
- `scripts/preview_health_vnext_conditional.py` 自动生成四份新旧逐例完整文字；`.github/workflows/health_vnext_conditional_review.yml` Python3.11/3.12 测试并上传报告，不能声称这4盘是秘密独立盲测。源库194案例、43章、81/42/17历史研究与失败记录没有修改。
