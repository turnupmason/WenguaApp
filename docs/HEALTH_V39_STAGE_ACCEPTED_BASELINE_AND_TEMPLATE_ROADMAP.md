## 以后的大量模板：不应复制一套新发动机

**第一层，全局公共底座**：四柱与节气、起局与九宫、用神/关系绑定、十二长生旺衰、旬空/入墓/击刑、值符值使、内外盘、星门神、81种有序天盘地盘组合的原文名称与条件、42条用户补充医学组合、17个候选复合条件、证据关系和原书溯源；这些应共享同一可追溯组件，但每项原书尚未核实的条件维持 unknown，不可假称全部实现。

**第二层，领域级解释**：健康疾病、恋爱婚姻、求职工作、经营求财、官司诉讼、出行、天气、考试等各自定义特定用神、主次权重、适用条件、反证与应期机制，不能把疾病的‘病吉/病凶’硬套成其它领域的结论。

**第三层，细分问事模板**：疾病领域仅将「病情轻重」V3.9列为阶段基线；医药效果、手术、出院、治疗出行、病程应期等须各有真实规则、例证与输入验证；绝不可因 V3.9 获阶段认可就自动启用或视为验收。

**第四层，客户呈现**：简洁自然中文、隐藏内部书籍行号/SQL/SHA/来源技术语；保留可核查的格局名称、方向、人物主用神、多重正反证据，以及有根据的实际宫位；避免反复抄同一句证据和未触发条件。

每个新增模板均执行：
`原书来源和规则条件 → 实际起盘与人物取用 → 多条正反证据 + 优先级 → 原时辰开发样例与未用来调参的案例 → 完整客户断词 → 用户阶段评审 → 独立新版本/不可变归档`。

## 软件与 UI 的边界

用户本轮明确「先这样」，表示当前疾病轻重细分模板暂告段落。**不立刻启动 UI、不声称 iOS 可提交 App Store**。今后若用户明确要求 UI，则以多个领域可扩展的通用输入、九宫盘、证据、结论、资料来源分层设计，而不是将 V3.9 单一病情轻重界面锁死成整个软件。用户明确要迭代其它模板时，从上述公共层复用，不要求再次粘贴已提供原书和用神方法。

**后续变更必须新建版本 V4.0 或其它递增版本，并追加独立数据库／测试封存；永不覆盖 V3.9 原样模板或断词。**
