产品目标是专业、可追溯、无需网络或 LLM 即可完整运行的“问卦”手机 App。当前以《神奇之门》《开悟之门》为古籍基础，统一按真实问题、人物关系、时间、一件事一盘，先核对历法节气、阴阳遁、局数和四柱，再算完整时家转盘九宫的神、星、门、天盘地盘干、旬空真假、马、墓、六仪击刑、门迫、五不遇时、伏吟反吟等；中五宫不能伪造普通星门神。真实十干十二长生、源81有序天地格、古文、原书例案均须保留出处/规则状态。人物用神根据领域、子题、本人或代测、年命和性别必要条件决定；没有出生资料不得推造年命，长辈按真实情况看乾或坤，非长辈不得乱加。

**V8.0 疾病轻重是当前锁定基线**：精确 Python 源算法是参考实现，Swift 本机实现必须与其事实、能量、条件、积分、段落文字完全一致。每一枚真正选中的用神（天芮、天心、乙奇、值符、患者用神、时干、年命、乾坤辅助，及未来领域的新用神）都用自己的符号身份、月令和实际落宫查原始200格/八神五关系等源强度；“极大、大、中等、小、极小”是**该枚用神的作用力量**。真实落宫星门神、81格及条件给出的带正负号 ±1…±5 是**整宫吉凶程度**，绝不能把 +5 或 -5 的绝对值当此宫任一用神的力量。先算每个实宫基础分，天干已进入81格不能再当第五类重复加；再审空、墓、刑、门迫等；最后按经验证专题条件加减，汇总裁切±5。不同角色同宫，基础宫分只累计一次；但天心和乙，或天心、乙、值符、时干等任意不同真实符号无论如何共宫，都必须**分别读取强度、保留作用证据**，不能采用第一个角色的能量或成败覆盖另一个；相同符号承担几个角色也不能重复算自身或自己临自己。

**所有宫对宫都遵守这个通用原则**，不限于“克病”：克、被克、生、被生、比和及同宫，先识别两侧真实用神，再取各自强度，最后判断实际宫位五行方向、空亡和来源条件。克的有效性由用户原始有方向的正常及真假空5×5矩阵判断，绝不能靠净宫分做“强制”。疾病既有条件加分：符合来源格方能 +3，病宫空且有效克制可 +5，施力受空或宫克且仍有可用作用才 +1；未核准或力不可唯一确定不给成功分。生、比和、同宫等若无独立已核积分矩阵，不得虚构新的加分。特殊同宫乙/丁奇一组，天心、值符各按真实独立符号/强度处理，入墓击刑或空亡按已冻结条件；整宫吉助统一逢空折半，不逐角色重复。五不遇时每个实际参与实宫扣2；伏吟主慢、反吟主快，必须据真实整局条件。

**仅疾病专题当前已通过 V8.0 软件验收**：同事原盘己丑/戊辰/辛卯/丁酉，V8 -5 极大凶；1920年女性长辈原盘己丑/庚午/丁亥/乙巳，V8 +3 中吉，年命须真实立春后才能绑定。用户后续告知历史反馈：同事后来病逝、女长辈后来康复；这两例现在是**已见答案的开发回归**，绝不能再叫秘密盲测，不能因为它们相符就声称医学预测已被科学验证。成功记录 docs/HEALTH_V80_SELECTED_POWER_TWO_FIXED_CLOCKS_RUN_40621011300_ATTEMPT_1.md，Actions #40621011300 包括 25 原矩阵配对、72 同宫/空亡组合、原2盘和新20随机时辰 Python/Swift 逐字一致。以后修改当前规则先做更大组合及新的未见样本回归，确保没有无意改分；未获我同意不能改掉两张已经确认的 V8 口径或用户认可的断词。

**跨领域需举一反三，不要直接照搬病宫专题加分**。未来婚姻、就业、求财、出行、升学、刑事、失物等不同领域，每个应有清楚来源的主辅用神、角色绑定、格局优先级、成立与不成立条件、冲突判断、应期触发器、唯一实宫计分及独立符号强度；婚姻尤其须按原书考核乙庚、六合、值使、六仪击刑、入墓、伏吟反吟、日月太岁等。不同专题同一来源概念共用规则库，原书不同意见保留多版本和书段/行号/hash，不要硬套健康模板或以GPT补古文。失败古籍案例必须留档；历史事件家族不得跨训练验证集合泄漏，不用已见案例反复调参再称盲测。

**Swift/Xcode 是产品唯一交付路径**：工程 ios/WenguaAppUI/project.yml 由 XcodeGen 生成 WenguaApp.xcodeproj；源入口 WenguaDesignPreviewApp.swift → WenguaNativeCore → WenguaNativeReadingRouter → WenguaNativeVNextEngine → WenguaPythonVNextVerbatim → WenguaNativeCustomerView。200能量 JSON、81天地格 TSV、人物角色 JSON、V8.0 reading_template.json 必须作为 iOS bundle 资源。每次逻辑/模板变更必须跑 Python 单测、Important 源镜像 hash、真正 native swiftc、同一时辰全文严格逐字比对，并在 macOS Actions 用 XcodeGen + xcodebuild 编译完整 SwiftUI iOS Simulator App、核实包内四类真实资源；不要把 Ubuntu 命令行 Swift 成功冒充 Xcode UI 构建，也不把 simulator 构建冒充 iPhone 真机/App Store 签名。待下一阶段我正式要求 UI 时，继续原有问卦 Logo、五行颜色金黄木绿水蓝火红土棕、九宫大字号、四柱等宽、空马墓刑可视、宫详情、领域子题选择、真实当前或手动时辰、静心30秒、同一事项15天限制、离线不显示内部评分术语，严格修当前工程而不重建UI。
