# 数据库与模型的长期更新节奏

2026-11-05，用户明确确认：**数据库持续更新，模型按版本集中微调；继承已经学到的权重，循序渐进。** 此规范覆盖历史“每次都从官方基模创建全新适配器”的默认安排，继续禁止不明模型、非书教师和旧人工计分适配器混入纯来源课程。

## 资料更新

资料先经过来源核对、条件与人物关系审查，再进入版本化知识库。原文、整理、原书错断、后来披露、事后反馈、作者更正分别保存。新增与纠错不要求立即重训；修订内容不覆盖冻结原文或当前训练的来源快照。新增古籍保留独立的书目、章节、来源版本和坐标。

数据库不是模型权重的实时镜像。[两书独立RAG](WENGUA_TWO_BOOK_RAG_20261105.md)现提供全章来源索引、条件包、历史案例与程序起盘适配；更新经核对的索引即可用于检索，不需每章重训。当前V5.1训练入口仍使用固定教材包，独立RAG不改其运行合同；模型问答只加载已完成封存的适配器，真实8B实答效果还需本机检查。不能把资料入库说成模型已经学会。

## 集中微调

积累一批通过审核的新知识、条件题、案例和纠错，再制作新课程版本，混合经过审核的旧知识复习。已知错误答案须修正或退出正向教学，不能把冲突答案当成扩量。

选择有明确来源、结构兼容且经实答评测认可的父模型或LoRA权重。父权重、教材版本、参数、评测与来源哈希一并保留。以后若从V5.1进入下一版，应在新版本中核准V5.1的父模型来源；当前V5.1的父来源检查和训练合同保持冻结。

换教材开始新阶段时，当前项目采用继承权重、新建优化器及学习率计划的方式；模型已学权重保留。同一阶段中断时，恢复模型、优化器、调度器、随机状态和训练进度。不能把新教材训练冒充旧样本顺序的精确续跑。

每版比较父模型与各epoch的实际回答，检查知识正确性、条件变化、证据完整性、跨领域取用和旧知识遗忘。低loss、更多epoch或更多改问不能单独证明进步。已看过的题单列诊断，最终测试不用于调参；材料不足时明确记录，逐步补充独立案例。
