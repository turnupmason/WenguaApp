### “作者知道什么”必须按顺序

案例1：作者已经判断手术历史和1991年后，患者才报告出生年。不能把出生年提前作为作者初断的输入。

案例3：作者已经做了前两条分析，求问者才进一步说出具体伤情。后续第三、第四步的上下文与最初第一、第二步不相同。

案例5：现场作者断案之后才有当事人的逐项确认，不能把反馈预填为问题。

案例6：报告的后续疗效及他人求医经历是书内转述，不能当作医学有效性的独立验证。案例整体书写完整，不等于预言科学有效。

### 第四例的跨章五不遇时校验

第六章曾列“庚日丙子时”的五不遇时对照；本疾病章第四例给“庚申日丙戌时”并把其判为五不遇时。两者日干/时干相同，完整时辰支不同。当前两份原书都真实保留，记录在 `source_audit.json`；需查清作者列举是否举例还是穷举，及按“时干克日干、同阴阳”是否扩张到另一个时辰。**不应由仅10个完全匹配的时柱表直接宣称否定原作者，也不能未经审核将全部丙时视为自动合格条件。**

## 保留的边界

1. 所有新数据均为 `draft`；古籍自述的疾病名称、寿命、病情和治疗判断不等于医学事实或可靠预后，App 不得凭盘断言真实疾病、死亡日期或替代医师诊疗。
2. 六例的“完整”指**书中完整的九宫文字与作者论述**；并非独立原印刷图、历法自动起盘或临床结果已经核实。
3. 当前公开 GitHub 可复现研究元数据和导入代码，但不能恢复全文；用户应保存本次私有 SQLite 与章节TXT。
4. **新增六个事件家族，不能机械拆为29个独立故事，也不能把同一故事的片段同时用于训练与独立测试。** 全部暂未进行训练/验证分配。
5. 下一章仍先记录该领域取用和作者步骤再处理全案，并更新 `AGENTS.md`、`docs/PROJECT_STATUS.md`、`docs/CHAPTER_LEDGER.md` 与GitHub CI。
