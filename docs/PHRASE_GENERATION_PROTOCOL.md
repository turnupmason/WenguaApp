## 用户已确定的长期目标

- 阶段序列：先完成婚姻短语数据库、质量门槛与模型润色，再同一逻辑一个领域一个领域推广，不按书另建孤岛。
- 1080是互不重复的完整**起盘状态组合索引**（阴阳2×九局9×六十甲子时60）；目前仓库`src/wengua/core.py` 对应状态值为 `index_only_unverified_chart`，**尚未证明1080张完整九宫已全部被现有起盘引擎正确算出**。此两件事不可偷换。计算器经实际规则核验的完整九宫JSON，才能实例化短语节点。
- 每领域理论情境：1080×60年命×3年龄段（young/adult/older）×2性别=**388800基础坐标**。代测关系、两方年命、具体婚姻问题会增加维度，但不是简单将其固定配一条结论；绝不因为同一基础索引就断语相同。
- 全量物理（术数）因素检查与用户可见文字长度分离：每个因子在内部留“实际触发/不触发/不适用/未知”+条件、原书引文、宫位和时序；成文可自然说明最关键的2~4条证据，不要逐项复述全部核查内容。
- 正确性来源层次：引擎九宫事实与因素计算可确定性核对；古籍作者推理是来源证据与示例，作者错误和老师后见修正分离；GPT只是自然语言表达与原型起草，**不是规则权威**；实际婚姻进展要以双方真实沟通与行为为准。

## V1.1 用户强制新增：做成败判断并真正算应期

用户明确指出以前示范所说“有驿马就可能变化，等空亡填实再看”没有实际断案价值。现在完成一个用户盘的定义是：**输出具体成败结论、针对被问事件选择应期粒度（年/节气月/干支日）、给出已经通过本地历法核验的公历起止时间窗口、列明原书取用/应期规则及正反证据**。可将时间预测标示为传统奇门方法下的推断，不能把未来发生与否当成科学确定事实；但不得用空泛避险句取代结果。只在主用神、完整盘、来源方法或者时区/历法真正缺失时返回真实`unresolved_missing_decisive_evidence`，必须列具体缺项。

固定流水线新增强制“**应期实算层**”：从全盘结构得出出空条件和落宫 → 日干支/旬首/旬空、近远空 → 填实、冲实、墓库出库、伏吟逢冲、马星发动等**有证据**的应期候选 → 已核的节气月或日历的干支区间 → 互证筛选最终一个首选窗口和必要的次要窗口。不要让GPT根据阳历月份自己算干支，更不要把术数符号当成自动事件成败判定。工具`src/wengua/timing_engine.py`可对引擎提交的**带时区完整期间表**推算冲实/填实时间，且不声称已独立认证输入历法；实际最终计算要有可验证的起盘与历法receipt。由`finalize_traditional_decision`验证输出不是虚构时间。

《开悟之门·恋爱婚姻预测》王大妈问儿子婚事（1998-11-09）书源第39/41/43/45行展示实例：乙庚比对、年命、六合落宫及甲申旬午未空，子/丑月冲实选择年底至次年初的传统应期；书内反馈12月16登记、1月17婚礼。该反馈是评测层，首断阶段不得倒灌。不同婚姻子目标（谈成、领证、办婚礼、离婚、复婚）分别生成结果/应期，不能把登记时间说成婚礼时间，更不能从未给日期的盘随意捏造天干地支。

当前4个约200字婚姻原型**仅用于自然中文风格和条件绑定研究**，尚未包含经起盘核验的完整终局应期，因此不能作为已完成的成品断语或已覆盖388800个节点。接入真实九宫后，要么产生带结果日期的独立`phrase_context_instances`，要么有具体缺失/矛盾的拒绝记录。后续逐领域同一套标准。

## 2026-10-21 USER CLARIFICATION: DOMAIN INTENT ROUTING, NOT PREWRITTEN ALL VERDICTS

**明确架构：不是给每个大领域、每个小问题、每个1080盘都提前写死一条结论。** 提前整理的是两书中每个领域的基础知识、可复用取用神/证据/反证/应期方法、按小问事划分的决策目标，以及用于自然中文的表现规范。每次用户传盘JSON与真实问题时，先根据问题识别`domain -> intent -> target_event`，计算盘面所有因素，依据问者与被问者关系选主辅用神，检索作者实际证据链及其错案和书源限制，形成**这个问题专属**的成败判断与首选应期（由真实历法和证据计算），最后由GPT将已得到的结果写成约200字自然断案话语，才落实际实例表缓存。
