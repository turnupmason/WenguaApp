# WenguaApp 断语生成统一协议 V1.0 — 从婚姻领域开始

## 用户已确定的长期目标

- 阶段序列：先完成婚姻短语数据库、质量门槛与模型润色，再同一逻辑一个领域一个领域推广，不按书另建孤岛。
- 1080是互不重复的完整**起盘状态组合索引**（阴阳2×九局9×六十甲子时60）；目前仓库`src/wengua/core.py` 对应状态值为 `index_only_unverified_chart`，**尚未证明1080张完整九宫已全部被现有起盘引擎正确算出**。此两件事不可偷换。计算器经实际规则核验的完整九宫JSON，才能实例化短语节点。
- 每领域理论情境：1080×60年命×3年龄段（young/adult/older）×2性别=**388800基础坐标**。代测关系、两方年命、具体婚姻问题会增加维度，但不是简单将其固定配一条结论；绝不因为同一基础索引就断语相同。
- 全量物理（术数）因素检查与用户可见文字长度分离：每个因子在内部留“实际触发/不触发/不适用/未知”+条件、原书引文、宫位和时序；成文可自然说明最关键的2~4条证据，不要逐项复述全部核查内容。
- 正确性来源层次：引擎九宫事实与因素计算可确定性核对；古籍作者推理是来源证据与示例，作者错误和老师后见修正分离；GPT只是自然语言表达与原型起草，**不是规则权威**；实际婚姻进展要以双方真实沟通与行为为准。

## 六层强制流水线

1. 规则可复现九宫与节气、时区、局数验证；
2. 刑破冲害、击刑、墓/库/门迫、空亡远近与填冲、驿马、暗干、旺衰、宫门星神干、五行、格局、反证完整audit；
3. 问者与被测人关系图（自测、长辈、子女、夫妻、朋友同事），婚姻用神按原书乙庚、六合、年命等动态选主辅，不机械等号；
4. 两本婚姻章节及跨书历史整案、错案的阶段隔离检索；
5. 证据加权不能自定缺乏来源的物理百分比，矛盾/unknown必须考虑，给有边界的结论；
6. GPT约200字、自然中文像真人说，不新增事实、不仿佛可靠测出外遇/生死、没有充分条件不编应期。

## 数据模型与验收

SQLite migration `schema/migrations/038_marriage_phrase_library.sql`：域进度、研究候选断语、每断语多本出处、完整盘后才可实例化的坐标节点、构建/审核追踪。短语来源位置与候选情境做双向关联，独立候选与人工/测试认可批准状态分开。不在 `cases` 表重复写婚姻历史样本。

- `draft` 断语不是用户可使用的吉凶输出；源书案例虽然按用户要求无需逐件手工复审，不意味着GPT新造方法与文案无需质量测试。
- 没有来自真实起局引擎的九宫JSON，不允许将仅有状态索引虚构成盘面的出词节点。有限示范只是*假设条件成立时可能采用的表达风格*，不是已知某个盘判断。
- 预计先可检验: 现有194整案与43来源保持完全不变；新域注册1；婚姻研究候选数>0，已验证坐标实例0，批准数0；全因子契约代码与测试覆盖缺少输入/冲突/状态错误；原书SHA/行号足够精确；中文文案自然不出现源码枚举名。
- 之后从最小可复现、已核九宫JSON开始：自测婚姻→母亲代问儿女→婚后/离婚/复婚→第三者猜疑→应期；每轮只提升经过来源与盘事实支持的结构化规则，原型写进新行而非覆盖版本。
