## 用户确认与旧版冲突

用户屏幕实图显示某宫「天芮／禽」与戊、庚、丁等干；原UI把所有天盘干放在八神同一行，容易误认归属。**正确归属必须以当盘 `WenguaNativePalace.heavenStars[].star` 与各自 `carriedStem` 成对为准，`earthStem` 是本宫同一地盘干，不归属某星独占。** 不根据图片推定不存在的第二天盘，不把示例文字写死为真实时间盘。

原 2026-10-24 Python `src/wengua/health_quant_overlay_vnext.py::quantify_palace` 对疾病病宫只有天芮本星与天芮携干的一个 81 格参与，即 `illness_top_stems` 和 `only_tianrui_carried_stem_if_illness`。原 Swift `ios/WenguaAppUI/WenguaNativeVNextEngine.swift::evaluate` 同样在疾病时提前 `continue`，滤掉天禽所携干的格局；`WenguaPythonVNextVerbatim.swift` 和 `health_palace_detailed_vnext.py` 解释亦滤掉第二个真格。这导致原病宫可见两条真实天盘／本宫地盘格局，却只统计/叙述一条，属于用户本轮明确批准纠正的来源遗漏。历史原代码、冻结原版、失败记录不删除。

**新限定规则**：

1. 只有疾病天芮所在实宫，如果真实 `heavenStars` 有天芮和天禽携带不同天盘干，沿星→携干一一绑定，得到两条独立的 `(各自天盘干, 同一物理地盘干)` 有序81格；按用户当前81 TSV 两条各自的吉／凶、月令/十二长生、天盘对应墓、刑、地盘对应限制分别评分，再合入**一个病宫基础分**。天禽**本星**仍不是第二个天芮病星基础分，不伪造中五普通星门神。若没有真实第二星或该格未能核准，不补另一条。
2. 病宫的同宫治疗乙／丁奇判断仍先按源200格力量、天盘/地盘身份、墓刑迫、空亡及独立目标用神身份判断。普通宫乙／丁奇仍选**同一物理宫最优一组**，不按角色数叠加。**只有病宫确实有两个不同星、两条不同天盘干，并且这两条天盘干分别恰为符合现有条件的乙／丁奇时**，允许两个不同符号各按源格规则1/2/3分独立累计（例如都强且无刑墓：3+3=6）；只有丁、另一颗不是乙/丁，则只取丁的一个奖励；地盘乙／丁不额外复制成第三份；同一乙身兼人物/时干也不得自助或重复。逢空在整个物理宫已合成的护持奖励上仅一次折半。此项不是两个完整病宫/病星基础分，更不是所有宫放开去重。
3. Python `disease_dual_sky_bonus` 测两独立星/干的源身份，Swift `diseaseDualSky` 使用真实 `p.heavenStars` 及候选匹配，正常非病宫`special_cohost_total` / `cohostPoints` 默认仍只接受单个0-3的奇门家族。两端严格按同一物理事实；客户全篇仍需要逐字一致，不能由UI决定分数。
4. 现行所有单个原书/案例记录和两个已见事件均保留**原先结果与新规则重跑结果的版本差异**；此增量是用户批准的新分支，不将重跑后差异称为历史未见预测成功，更不能为固定-5/+3偷偷调参。如果出现冲突，严格报告实际字段、盘面和来源。
