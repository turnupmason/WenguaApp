# 纯古籍Qwen3-14B本地自动训练循环

2026-11-04。用户授权把新纯古籍课程做成可连续运行、跑完统一看结果的loop，并说明4080和时间都可用于深入训练。新入口 `run_qwen_book_loop.py`，Windows入口 `run_book_training_windows.cmd`。旧V2和旧混合V3仍撤回。

## Windows启动

在现有4080电脑的CMD执行：

```bat
cd /d "%USERPROFILE%\WenguaApp"
git pull --ff-only origin main
run_book_training_windows.cmd
```

优先离线复用已下载的固定版本模型，只有明确缓存缺失时才下载该官方版本，避免每轮反复请求Hub可选文件。沿用用户之前已经成功训练14B的 `local\qwen_env\Scripts\python.exe`。不使用系统WindowsApps的python，不使用Mac的bin路径；批处理自动切到仓库目录和UTF-8。Git拉取失败时先解决拉取错误，不运行旧脚本。

等效Python命令：

```bat
local\qwen_env\Scripts\python.exe -X utf8 run_qwen_book_loop.py run --output local\qwen_book_loop_v3\run1 --cycles 6 --hours 48 --resume
```

首次启动自动创建新任务。再次执行相同命令会恢复同一任务；已完整完成的任务只重建报告，不再训练或重复最终测试。达到48小时会保存并暂停，可再次用同一命令继续剩余有限轮次。CLI单次上限168小时，轮数上限6；不存在无限循环。默认验证连续两轮未改善时提前结束。

## 自动完成的工作

1. 读取固定两书原库和原案行号索引，重新生成纯书源核心任务。不需要手动把百万ZIP移到Windows，也不会下载或生成百万同义题后盲目全量重复训练。
2. 对实际选中的每轮自然对话逐条分词。每个核心每轮最多一种问法，每个assistant回合有单独监督前缀；验证和测试来源家族不进入训练。完整长案留档，不截断条件或原盘。
3. 在4080上优先做4096-token、两步优化的最大样本显存短测。只有CUDA显存不足才退回2048；数据错误、磁盘错误等直接报告，不掩盖。选中上下文写入selected_config.json，此后恢复不能偷偷改变。
4. 探测和正式任务各有独立短测记录。探测／短测适配器不作为正式首轮权重；正式首轮从官方Qwen3-14B固定revision新建r8、q/v LoRA。
5. 最多六轮。下一轮只接本任务上一完整轮的适配器，并新建该轮优化器；不接任何旧V2／旧评分教师适配器。每轮换有出处核心任务的问法，标准答案始终来自两书，不把模型自己的回答回灌成教师。
6. 每25优化步骤保存优化器、调度器、RNG、Trainer状态和适配器，保留最近3份优化器检查点及各完整轮的适配器。数据、模型、代码或优化计划变化时拒绝误恢复；缺损／哈希改变的检查点不加载。
7. 每轮记录语言训练／验证loss，并对同一组最多16条独立来源组题目生成原模型和各轮原始回答。原模型基线只生成一次，问法、上下文和seed一致。完整参考答案超过生成预算时留明示排除记录，不截短参考答案充数。
8. 按固定验证集语言loss选“适配器中最低loss检查点”，同时报告与原始Qwen的loss比较。loss和字面相似度都是诊断，不是专业正确率；不能据此宣称会独立断案。
9. 全部有限轮次结束或早停后，只对选中的适配器和原模型做最多64条独立来源组最终测试。中途暂停不消耗最终测试；已做的完整测试恢复时不重复。

## 所有结果的位置

直接打开：`local\qwen_book_loop_v3\run1\results.html`。

报告包括每轮loss／步数、状态、完整提问、原模型回答、各轮回答、参考答案、古籍原文和出处、输出是否到达长度上限，以及全部保存的逐步训练日志。HTML离线可用，中文和模型输出已转义。

训练子目录 `run1\training\` 还保存：

- `results.csv`、`training_steps.csv`、`summary.json`、`job_status.json`。
- `selected_checkpoint.json`：所选轮次和实际适配器路径。
- `generations\validation_base.jsonl`、`cycle_XX_validation.jsonl`、`final_test_*.jsonl`：全部原始回答。
- `cycle_XX\adapters\step-N\`：各轮适配器、分词器与文件哈希收据。
- `cycle_XX\trainer\checkpoint-N\`：优化器等恢复状态。
- `prepared\receipt.json`、长度排除表与原文／核心记录：实际训练数据、来源和审计。

4096和2048的实际六轮语料均已用官方分词器检查。4096每轮4875–4876回合，约610优化步；2048每轮4812–4815回合，约602步。四类都参与，但超出上下文的完整材料保留，不能称所有原案都以一条完整输入参与训练。百万问法是候选池，本次有限课程约2.9万监督回合，避免让近义包装获得百万次额外权重。后续是否扩大由实际回答错误与来源覆盖决定。

## 暂停、恢复和错误

数据准备阶段中断时，未开始训练的半成品会先完整改名留档，再自动重建；训练开始后若数据收据丢失则拒绝猜测恢复。Ctrl+C或断电后保留任务。再次执行同一批处理会恢复最后一份完整优化器检查点。若步数已达到上限但状态尚未写完，只整理适配器和评测，不额外多训一步。语料或配置改变需要另一个output目录，旧输出不覆盖。Windows运行期间阻止系统自动睡眠，退出后恢复此前状态；不修改电源计划、不自动关机。

若4096和2048均显存不足，保留context_probe.json与failure.json后停止；不能声称已验证16GB适配。程序无法远程控制用户电脑，当前实际14B/NF4显存和训练质量均须以本机探测及报告为准。

## 软件验证边界

标准库测试覆盖旧配置／旧适配器拒绝、同任务恢复合同、损坏检查点、来源缓存篡改、OS互斥锁、完整答案预算、CUDA OOM专属回退及测试集不参与选模。真实微型随机Qwen3 CPU测试实际跑过短测、一步中断恢复至两步、下一轮接同任务权重、新优化器、同题原模对照、最后测试与完成后幂等恢复。另验证“已满步数检查点但未提交状态”的断电窗口不多训。

这些是训练控制的实际测试，不是14B/CUDA实训，也不证明专业分析能力已经提高。病例原书复盘、原文辅助教学和明确初问视图在报告中分别标记，不能把提供作者资料的阅读题当新盘盲测。所有训练教材仅两书知识和作者案例；无旧人工计分教师、用户补充或旧模型输出标签。

补充：prepare子命令用于固定上下文的数据调试，其output应配合run --fixed-context；常规Windows自动循环直接使用批处理，不需要提前prepare或下载百万ZIP。
