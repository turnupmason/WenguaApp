# 本地量化模型 V1：目标定义、数据与 RTX 4090 训练入口

用户本次授权建立量化模型，训练可在自己的 RTX 4090 机器执行。本模块独立于已封存疾病轻重 V9/V11、病位 V27、当前应期 V4；没有修改这些规则、手机资源或 UI。不是恢复旧 27B 微调项目。

## 模型选择与百分比的含义

第一阶段使用 **CatBoost 表格模型**，对照事件先验、逻辑回归及相同背景信息的模型。输入来自起局引擎的确定性事实和问前已知条件；随后可扩充有来源的用神绑定、宫位间生克、旺衰、空墓刑冲合及相反证据。当前导出器只提供原书九宫符号和物品类别，**尚未把全部专业规则转换为统计特征**。不将原断词、作者判断或后续反馈送进特征。

| 问题 | 模型/目标 | 合理的概率输出 | 标签必须记录什么 |
| --- | --- | --- | --- |
| 病在哪儿 | 每个部位分别建二分类，多标签 | 某部位存在问题的概率；可同时多处，不要求各部位之和为 100% | 问事时的实际部位、诊断依据、哪些部位真正检查过；未提到不等于正常 |
| 病情严重性 | 有序等级模型；起步可用多分类 | 轻/中/重/危重分布之和 100%；重症概率为重与危重之和 | 同类疾病预先确定的客观分级和评估时点；不是把奇门分数除以满分 |
| 病什么时候好 | 离散时间竞争风险生存模型 | 7/30/90 天内达到指定康复标准的累计概率；同时处理死亡和仍未康复 | 起问日期、康复标准与日期/区间、死亡日期、最后随访日期、治疗背景 |
| 失物能否找回、何时找回 | 找回事件的生存模型 | 1/3/7/30 天内找回概率 | 起问日期、实际找回日期、最后查找/确认未找到的日期 |
| 失物方位 | 方位多分类 | 从事前约定参照点看，八方向或就在参照点的概率分布 | 参照点、位置目标时刻、实际方位或坐标；不能拿预测方位当真值 |
| 失物在哪个场所 | 候选区域分类，逐层条件定位 | 家/车/单位/室外/候选之外；再细化房间、容器 | 搜索前的候选清单与实际位置；真实位置不在候选内时也要保留 |

数字示例仅解释定义，不是本项目预测结果：“东北 45%、东 25%、其余 30%”是在同一参照系和时刻下，对互斥方位的分布。“卧室 60%”与“东北 45%”不能直接相乘；若要说东北卧室，需要学习联合分布或真正的条件概率。查找到的位置也不一定是起问时的位置，车辆被移动尤其如此。

康复应期不能只在已经康复的人里估计日期，再让所有人都得到一个康复日。`cumulative_incidence()` 已实现竞争风险累计：每段在仍未结束的人群里估计康复、死亡、继续三种状态，再累计为无条件概率。尚在治疗且失去后续记录属于右删失；死亡属于竞争事件。**V1 尚未实现带删失权重的生存训练，也没有导出可训练的医学时间集。**

百分比要检验校准：在没见过的事件中，预测约 70% 的一批，实际是否约七成出现目标结果。不能把最高类别分数、规则强度或作者自称应验率直接称为真实准确概率。位置还需看前 1/3 候选覆盖和角度误差；时间需看不同期限的删失校正 Brier 与区间覆盖；病位需看每部位漏报、误报和校准。

## 实际数据与当前完成范围

源库：`archives/sqlite/WenguaApp_双书194案例_V391纯断词十二长生_完整研究库.sqlite3`，完整 SHA256 `21362e6f0266c03dcdc4a7ef35f45954ba274ae6458de0ba341132abca7d0405`。只读打开、核验字节哈希与完整性，不改原库及 reviewed/training 标志。194 个事件、43 章；其中疾病 12、失物 13。194 不是每种任务各有 194 个标签；1080 局也不是 1080 条独立结果。

本轮实际实现：

- 全库清点；带反馈与宫位来源收据的失物试验导出；完整九宫与问前字段白名单。
- 二/多分类本地训练：CatBoost 的 CPU/GPU 参数、逻辑回归 CPU、事件加权先验和背景对照、逐事件留出；较大数据的固定分组训练/校准/测试与温度校准。
- 模型保存、逻辑回归可移植 JSON 推理、CatBoost 本地模型及哈希、分组预测与指标报告、原始运行目录防覆盖。
- 方位参照验证、竞争风险累计接口；其余领域是明确的数据/目标契约，不声称已经训练好了病位、临床轻重、定位或应期模型。

首个真实数据试验目标为 `lost.recovered_at_last_report`：**某件具体物品在书内最后反馈时是否报称找回**。登记 14 个物品目标、13 个事件；首版严格导出 12 行、11 个事件，10 件找回、2 件未找回。公文包找回和包内现金未找回是同一事件的两个目标，每行半权重、始终同折。另两项保留登记但不训练：一例初问是六爻、后学奇门复看，不能伪装成初问奇门样本；最后执照例在本适配器的主宫表缺完整九宫，不表示其它来源表也没有盘。

此二分类试验的随访长度不统一，只检验真实数据管线，不能解释为最终找回率或 7 天找回率。病例是书内报告，没有独立外部验证。没有把鸡病与人病合并训练、把后来去世当初始重症标签，或把作者“断对”当事件成功。

数据少时运行逐事件留出，**不拟合校准器、不输出用户百分比**。较大样本（当前工程分支条件为至少 60 个事件且每类至少 10 个事件）采用预先固定的组哈希分区；这些数量只是工程协议条件，不代表科学有效的最低样本量。训练、校准、测试必须各有目标类别，否则明确失败，不根据测试表现换分组。即使拟合了校准器，也只输出研究百分比，`production_enabled=false`，不自动发布到手机。现有历史验证没有完整时间先后检验；未来须记录可用日期并另做向前时间验证与前瞻外部验证。

## 在 RTX 4090 机器运行

建议 Python 3.11 或 3.12。当前少量表格数据用 CPU 很快，4090 的主要价值在数据扩大和更复杂模型阶段，不必为了使用显卡增加参数。GPU 训练需要兼容的 NVIDIA 驱动；当前环境没有实际 4090，GPU 执行未验证。

在仓库根目录创建隔离环境（任选本机方式激活）：

```bash
python -m venv local/probability_env
# Linux:
source local/probability_env/bin/activate
# Windows PowerShell 对应： .\local\probability_env\Scripts\Activate.ps1
python -m pip install -r requirements-probability.txt
python -m scripts.probability_research export
python -m scripts.probability_research train --backend logistic --output local/probability_v1/logistic-run1
nvidia-smi
python -c "from catboost.utils import get_gpu_device_count; print(get_gpu_device_count())"
python -m scripts.probability_research train --backend catboost --device GPU --output local/probability_v1/catboost-gpu-run1
```

CPU 替代命令：

```bash
python -m scripts.probability_research train --backend catboost --device CPU --output local/probability_v1/catboost-cpu-run1
python -m scripts.check_probability_training --backend logistic
python -m scripts.check_probability_training --backend catboost
```

每次使用新输出目录，失败/旧运行不覆盖。结果：`inventory.json`、`rows.jsonl`、`evaluation.json`、`heldout_predictions.json`、`model.json`，CatBoost 另有 `model.cbm`。前 2 项在导出目录，其余在训练目录。模型分数不是置信区间；不能因为一面倒的“找回”案例占多数，就把全猜找回的命中率称为模型能力。

自定义同一目标的训练数据以 JSONL 传给 `train --input`。字段参照真实导出行：事件家族、具体目标、已知结果、原盘九宫、问前结构化背景与结果收据。未知结果留在待标注库，不填失败。不同目标分别训练，未检查部位不填阴性；多张盘/多次重读不增加独立样本。当前通用训练器不自动展开多标签、有序阈值或生存人时数据；不得把这些尚未实现的转换伪称已接通。

公开仓库提交程序、目标契约、原创标签摘要/哈希和试验收据，不新增大段原文或私人问事。工作数据默认在 Git 忽略的 `local/`。独立模型 CI 检验 CPU 软件兼容和事件隔离，不等于医学或预测效度验证。

后续优先工作：按各目标补齐真实结果与时间/位置参照，审计逐案信息时序，将已有专业规则转换为可审计特征，再做同背景下加盘/不加盘对照。若数据足够后要用图网络，可把九宫当节点、生克等定向关系当边；当前不预设图网络胜过表格模型，也不以更大模型补缺失标签。

## 本轮实际软件验收与试验结果

本地完整回归 **930 tests，0 failures，0 errors，3 个既有 skip**；独立契约/镜像 14 项通过。逻辑回归与 CatBoost CPU 都实际运行完整逐事件留出、保存/重载与逐概率一致性。另有明确隔离的 synthetic 软件夹具检查多分类校准分支和改变测试标签不改变训练系数/校准温度；它不在真实数据中、不计历史案例、不作为预测准确率。实际源字节收据与全日志在 `docs/audits/probability_research_v1_20261102/`。GPU 仍未实际执行。

| 真实11事件留出，事件等权 | 先验 | 背景逻辑回归 | 加盘逻辑回归 | 背景CatBoost | 加盘CatBoost |
| --- | --- | --- | --- | --- | --- |
| Brier（各类平方误差求和，越低越好） | 0.275884 | 0.276090 | 0.270229 | 0.335011 | 0.272215 |
| Log loss（越低越好） | 0.469911 | 0.516411 | 0.494780 | 0.515935 | 0.476298 |

两个加盘模型的留出类别都全判找回，与简单先验的事件加权准确率同为约86.36%；这主要反映类别不平衡。两者 Log loss 均未胜过先验，Brier 略低不能在11个事件上支持稳定增益结论。没有挑出更漂亮指标宣布预测有效，也未生成找回百分比。公开试验模型与完整报告在 `data/evaluation/probability_research/v1/`；这些是可重现的软件/研究起点。新本地模型工作流和主CI实测状态另在同目录审计收据中追加。
