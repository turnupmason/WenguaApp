# V4.1｜81组天地盘候选权重：对照原书后的改进方案（未验收）

## 一、必须先明确的三个概念
用户称「42组天地干」，但全文按天盘戊乙丙丁己庚辛壬癸 × 地盘九干，实际提供了**81条**有序组合。仓库原来还有**42条另外的疾病条件资料**、**17类复合条件**。三轨须并存。

1. **来源书原文**：`data/knowledge/kaiwu/analysis_judgment_ch04/ordered_stem_pairs.json` 的81条，保存每条真实天干上下、原句、行号、SHA；为方法基准。
2. **疾病专项补充**：`data/knowledge/phrase_library/health_v30/user_20261022_pair_catalog.json` 的42条，保存角色、病程、条件异议，不覆盖原文。
3. **本轮81条建议分值**：`data/knowledge/score_models/health_severity_v41/ordered81_user_weight_candidates.json`，存**全部81条、用户别名、数值或需新久病输入的数值**；数值是模型假设而不是书上原有统计系数，绝不可登记成原著的权重。

全局旧V3.9断词与V4.0未校准总分均保留为原样参考；新V4.1只能通过单独版本运行。

## 二、对用户表格的直接纠错

### 1. 病宫分数必须依符号所扮演的角色、古籍专项例外及实盘关系决定

不可简单写 `病宫 = - 该格局表分值`。数学上 `-(-20)=+20`，所以用户写的「庚庚-20 代入 -(-20) 得 -20」错误；同一个算式不能同时支持「庚庚继续-20」和「乙辛变+20」两种结果。

更深一层，**原书同一吉格在疾病问题中可以转成不利**，并非天芮所在宫一律把善恶颠倒。《开悟之门》原句确定：
- **戊/丙**原名「龙回首」，一般谋事大吉，但**测疾病并非自动吉**，作者明确说可能提示病重。用户草表给+20，V4.1记 `source_vs_user_positive_conflict`，不能直接给+20。
- **丙/戊**原名「鸟跌穴」，一般谋事大吉，但作者另说测疾病可能病重。用户+20同样被门控阻止，且不能因「病宫有吉格」直接推断康复。
- **戊/庚**原书「值符飞宫」，明确「测病也主凶」，仅在本问事真实患者宫/天芮主病角色中、经对应门控才记候选扣分，不能在任意无关宫位按分值罚。
- **丙/辛**原书「月奇相合」，明确「测人疾病也不凶」。用户写「谋事成就，新病+10、久病-15」并未从本条原文得到久病转-15的授权。病程未知就暂不评分，久病-15与本条原书冲突继续挂起。
- **丁/壬**原书「奇仪相合」，一般凡事有成。用户写「五吉化合格 -12 心脏肥大」无对应测病出处，不应把这个医学病名自动推断给任何患者。
- **庚/戊**原书「值符伏宫」，且明确会随主体到底是甲还是庚、主客而变化；用户表「天府飞宫 -12」不能当作唯一原书标题。并注意 **戊/庚与庚/戊不可对称**。
- **己/癸**原书「地刑玄武」，明确提疾病不利；患者宫实际命中可做**不利象意加权**，不能在病宫按数学负负得正，进而断疾病消失。
- **己/己**原书「地户逢鬼」，明确测病有不利传统判法；其原句包含极端生命预言，用户面向文本只宜展示传统“明显不利”，不能转成临床诊断或死亡预告。
- **癸/辛**原书「网盖天牢」，有测病不利的说明。原表用户称「天网牢狱」，应保留两种来源名称但最终以原书为主。

同时即使是“原书说测病主凶”，**不等于它落在天心医药宫、值符宫、空宫就自动扣患者分**；医生和药效必须有与医药角色相符的其他明确原著取用关系。

### 2. 月令、入墓、冲马须分角色且拆成多条事实

- 患者主用干、出生年命、主宫五行、天芮土本体、天芮携带的天干（例如丙）不是同一个旺弱对象。
- 天芮携丙在乾6：丙火戌墓、亥绝，乾6戌亥时旬空。它可**限制丙辛吉格**，但不能仅凭“丙入墓”推断“病毒已被封锁可以+15”。
- “墓/库”必须结合月令旺相休囚判；确有墓位置但旺相时为库，不可判“病危”。
- 用户建议**马星处于墓宫对宫/斜对**为“冲开墓”的候选；应分别记录真实墓宫、占时支起马、马支、马宫、九宫对位，并区别真正地支六冲（辰戌、丑未等）。如果没有真入墓，开墓不能凭空加分。候选70%冲墓退款是V4.0实验假设，不是书源或用户确认权重。
- 生门与死门各自独立；固定坤2地盘天芮本位和男乾女坤参考宫不可重复当两个病人主用宫。

### 3. 建议的六模块划分与计算细则修正

**模块一：患者主证 + 病星主证 + 月令十二长生**。按实际问事关系绑定主用神（自己日干、父母年干、同辈月干、子女时干、夫乙/庚等），不一律以日干/年命。已知年命只作另一宫参照，不假造。原资料 `stem_stage` 函数只有5个已索引状态：长生、帝旺、死、墓、绝；用户新要求其余七态（临官/冠带/沐浴/衰/病/胎/养）必须先溯源补全、交叉核宫，**当前不能用假定十二全态表自动扣20**。新久病对帝旺的作用应在真实病程输入后才会考虑，不能默认为久病。

**模块二：时干事体动态**。时干宫克患者可能是不利候选，但传统没有任何单张盘可以直接证实「未来越来越恶化」；与日干宫、天芮、值使同时核对。患者宫生时干 / 时干宫生患者仅依具体五行流向，加减方向须有原书专项支撑。例如「病宫生患者宫」旧规则视为得生扶，与用户新稿「病生人-10」发生内部矛盾，应先保留未评分，而不是择一造结论。

**模块三：医药与月令**。天心与乙奇两种医药信息可以分别展示，得益得损不得同宫重复算；医药虽月废，仍若与时干/天芮同宫，其求医机会应独立保留，但不声称药能治愈。宫空、门迫的影响必须归到对应医药角色，不是医学“假药/庸医”事实。

**模块四：刑冲破墓空及马星**。每个条件要有来源层、触发条件、被解除条件、否决条件、准确角色；区分患者宫旬空、新久病、时干刑、岁破、日破、门迫、六仪击刑，避免同一现实条件多重扣分。特别是墓冲时把原来墓分修正到（暂定）-5属于“原扣分调整”而非在-25上再叠加+25后再叠加+20。死亡、一票下20以及“下病危通知书”的现实医学命令全部禁止。

**模块五：81原书有序组合 + 42疾病补充组合**。每一个真实九宫天盘携干与该宫地盘干在有序库精准匹配。源码先判是否真在患者主用宫/天芮病星宫/医药宫/时干宫；天芮+天禽同宫允许同宫两组源记录，但不能按相同病势重复得失分；旧42条病程/角色修正层作为条件而非第2次分值投票。数值全部先作为候选保留。**医药/值符/时干没有专项书源不要继承患者宫的病凶分值**。

**模块六：17复杂格局及三诈五假、伏吟反吟**。仅已有完整原书可执行定义与实际盘满足才触发。三诈五假不等于临床“假性病变”；丧门/吊客/岁破等尚未有同档案的完整规则证据不应盲从传闻自动扣分。伏吟、反吟偏向缓急性质，不能无条件推断新病一定转好、久病一定死亡。

**终极协同层**：保留 V3.5/V3.6 已验证的「患者宫克病宫 + 病宫克天芮」**双重制病**；用户新提出的「患者宫克病宫+医药宫克病宫+天芮休囚」应另称「人药双控＋病星弱」而不取代旧定义；所有支撑证据按宫位/五行/关系去重，仅允许一次额外交互加权。双重不利也是可加重候选，但绝不一票覆盖<20、不声称病危或死亡。

### 4. 正确理解数字的刻度和模块预算

用户提议35%、15%、20%、25%已占95%，**剩下模块5、模块6及交互层没有数学预算**，如果直接相加，既非百分数也不是可校准概率。之前V4.0首次回放：2026自测原46，1995问弟弟原90（与旧古籍传统不利结论矛盾），1996本人原124（截断为100），证明100基准偏高及截断丢失证据。V4.1 **未宣告修复这些数学问题**，它仅先将81用户候选分值逐项导入、加上原书优先的激活条件，并保存所有未触发/冲突。不得把它称作“准确生命体征指数”“医学概率”，也不能以上述回放试题作调参以后又把它当独立盲测。

建议后续V4.2另做`module_budget`、50分中性初值/可逆归一化比较，与“未知条件下分值区间”一起基于其他未用来调参的事件家族评价；仍是文化占断模型，不是医学预测器。
