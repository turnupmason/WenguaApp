# WenguaApp V2.0 — 疾病五种子问事与前期人物关系选用神

## 本次正式采用的结构

用户确认病情严重程度21段详细断词样稿。全部前端文字只出现“依据古籍”，不显示具体书名、数据库主键、SHA、测试术语或“例如符合条件时”等空话。每个填空都由真实起盘事实、符号简短含义、该病情领域对应的传统象意和条件下的利弊组成。严禁只用一句话缩写整篇21段。

输入先选患者关系 relationship、问事情境 consultation_context、具体问事 intent 三个独立维度。已预先选择的关系对用神和宫位有决定作用，绝不能在起盘后随意替换患者日干。问事目标不同，必须更换推理流程和模板。

## 实际人物路由

依据古籍、目前古籍来源候选如下（完整机器档 data/knowledge/phrase_library/health_v20/actor_profiles.json）：

- 本人 self，direct_self：日干对应问者本人，天芮疾病、天心乙奇医药，源健康原案第67行。
- 父亲 father，direct_proxy：长辈年干候选，兼乾6宫，原书问父病第105行；出生年命如有再兼看。
- 母亲 mother，direct_proxy：年干仅为长辈通法候选，母亲另外参坤2宫。现无来源能证明所有母亲测病都永远指定同一干；类比来源状态必须保留。
- 朋友、同事 friend/colleague：直接代测按同辈月干作为待进一步核查的条件候选；若用户选择 event_news，即闻讯按事件时刻起盘，原书第43行明确以事件日干代表他人，不能混淆。
- 儿子/女儿/孩子 son/daughter/child：晚辈时干作为有类似侄子源例支持的候选；已提供性别和长中幼排行时可另参震坎艮/巽离兑具体子女象宫。亲生子女用法仍需更多专门原书核对。
- 侄儿 nephew：原书确有叔辈问侄儿用时干第145行，保留与儿女类比用法不同的来源强度。
- 配偶、兄弟姐妹、其他长辈：各自记录人物身份和取用候选；欠缺明确个人主用神的情形，不拿日干冒充病人。
- 出生年命 birth Ganzhi 可选，未提供就跳过，不阻碍检查天芮、医药、门神格局；出生年干与起局年干绝不互换。完整六十甲子才合法；甲隐藏干落宫未知时不编造。

## 完整模板与代码

病情轻重 severity：21段，完整详细近看远看、人体八宫内外部位、丁癸庚等天干疾病传统象、天地有序克应、九星月令专用旺相休囚废、八门、八神、门迫、旬空月破、患者主辅宫、医生天心、医药乙奇、全24项审计、互反证、可用应期及最终总结。

治疗是否有利 treatment：12段，优先核天心乙奇、病宫、开门医疗通路及患者承受，不能与轻重简单同论。
出院何时/恢复 discharge：12段，优先核事件目标、病困、患者用神与旬空冲填、动静及独立节气历法，不把恢复等同出院。
手术 surgery：10段，独立核开门、伏吟动静、患者与医药宫，不作为实际手术必要性决定。
异地求医 travel_for_treatment：11段，独立核出行目标、驿马、内外盘、开门、天心乙奇和患者宫，缺地点不发明方向。

五类共66段，机器模板在 data/knowledge/phrase_library/health_v20；引擎 src/wengua/health_dynamic_v20.py；CLI scripts/run_health_dynamic_v20.py；测试 tests/test_health_dynamic_v20.py。新增任何更细的疾病子问题（实际患病位置、慢性病、手术后恢复等）都要再写该子问题的独立方法与模板，不能冒用上述五类。

## 判读和安全边界

内部每一个符号保持原书章节、行号、SHA、条件、正反证及可核状态。病象上的头眼面、丁火血热、癸水道、庚筋骨、螣蛇反复等要由实际盘面和适用条件触发才输出，不能凑字。格局必须验证真同宫有序天盘干＋地盘干及星门神，门迫只有门克宫。没有准确源法的因素记未核实，不自动当吉凶。数字计分不凭空设权重；有原书复合格局则先合取分析，不重复记证据。应期需要真实事件目标、完整时空历法和真实古籍触发；没有就写暂不定日。古籍文化类象不构成真实医学诊断、病情分级、死亡风险预测、治愈率或手术治疗建议。
