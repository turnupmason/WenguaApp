## 数据怎样处理

- 引文回到原章节逐字定位，空白差异单列。8条未定位的摘要留档，不冒充逐字引文；4条缺来源/空内容不造答案。107个缺少本段字面支持的结构化字段不生成属性标准答案，原字段仍留档。88个图题、导航或过短片段不作解释题答案。
- 同一段被索引为多个概念时，阅读题排重；不同属性问题保留。短摘要同时保留原段后文的明确条件和例外，回答本题，不再统一写“以下是来源资料”。证据保留原句，不能把不连续摘录拼成作者连续原话。
- 原断言表未覆盖的《神奇之门》起局、应用概述两章，补入138个完整方法段落。5个涉及未注册历史轶例的段落保留在原章档案，不当新增独立预测样本。每章原文与索引覆盖率单独报告；这不代表已经证明全部文字无误或全部知识已学会。
- 儿女代问父病、本人自问、闻讯占事分开；年命必须来自真实出生信息。当前人物规则、用户应期资料与具名旧版补充分别归源，不将旧版本自动当成当前规则。
- 作者当时断语、原书后来反馈、作者纠错和现实独立验证分开。原抄盘只保留原列定义，不擅自把门行/星行当成天盘/地盘。
- 训练/验证/测试按来源和事件组固定切分。同源多题不拆分；原V1留出的事件不流回训练。原文、原字段、完整分析及失败样本保留，不为统一口径改历史。

课程的出处、数据结构和组间隔离已做程序检查；没有把整套自动制作结果标成人工专业审核通过的金标准，也没有声称传统断语已获现实预测验证。

## 在 Windows 本地准备和查看

使用已经安装好的 Python 3.12 `local\qwen_env`，不用重新安装环境。在CMD执行：

```bat
cd /d "%USERPROFILE%\WenguaApp"
git pull --ff-only origin main
local\qwen_env\Scripts\python.exe -X utf8 run_qwen_curriculum.py prepare --output local\qwen_curriculum_v2\run1
```

准备只需官方14B tokenizer，不加载14B权重。打开 `local\qwen_curriculum_v2\run1\data\qa_review.csv` 可以用Excel查看全部问答、上下文、具体答案和原文依据；UTF-8 BOM用于Windows显示。实际训练用原JSONL，不从Excel重导入。不要把含长原文的CSV/JSONL、完整trace或权重提交到公开GitHub。

同目录还有：

- `data/source_units.jsonl`、`original_source_tables.json`：来源与11张教学相关表的原字段导出；原SQLite共251张表保持只读，并没有声称全部转成问答。
- `data/case_registry.jsonl`：194案例、原始字段、分组和原协议。
- `data/source_audit_issues.json`、`quality_audit.json`：具体疑点及出处/格式检查。
- `prepared/token_audit.json`：逐条token长度、短视图、超长保留名单和两阶段课程数量。

1536 token的实际官方模板检查结果：训练11,101条、验证1,120条、测试1,055条可容纳；65条仍超长（49/9/7）不截断后强塞。8条过长的作者上下文改为保留完整作者原段的阅读视图，所有1,008个作者段落仍有教学样本。完整盘及全部披露仍在原档；短阅读视图不冒充完整盘推理题。

## 两阶段训练与断点恢复

准备后在同一CMD执行：

```bat
local\qwen_env\Scripts\python.exe -X utf8 run_qwen_curriculum.py run --output local\qwen_curriculum_v2\run1 --resume --hours 15
```

从官方固定版本 **Qwen3-14B** 新建LoRA，不接着旧V1固定摘要适配器重复加轮。第一阶段3,756条、第二阶段4,548条，含适量复习和盘面读取；同一来源的复习不是新增知识或新事件。当前配置每阶段最多一个数据遍历对应的步数，上限500/650步；这批实际计划470/569步。知识阶段学习率5e-5，复盘阶段3e-5，r8、q/v投影、NF4、1536长度、batch1累积8。完成即停，不强行耗满15小时，不自动重复训练。

每25个优化器步骤保存适配器、优化器、调度器、RNG和训练状态，保留最近3个检查点；阶段末另存适配器。每个完整检查点有阶段合同和文件哈希收据，半写入/损坏文件不会拿来恢复。相同阶段仅在数据、模型、代码、配置完全一致时恢复优化器；换阶段载入前阶段适配器并新建优化器。`--resume`显式允许接续同一私有任务，不覆盖旧V1输出。若代码或数据已更新，请使用新输出目录。

Windows训练期间临时防自动休眠，正常或异常退出恢复设置。截止前240秒请求保存后停止；不要同时运行两个GPU训练任务。`--hours`是上限，不是对完成时长或显存余量的保证。当前参数接近此前本机14B可运行设置，但本轮全量数据的实际4080训练还须看本机日志。

已启动旧等待器的用户：它只会在 `overnight_release.json` 切换为经过检查的ready版本后启动固定入口；索引候选稿本身不能解锁。没启动的用户可以在本版就绪后执行 `local\qwen_env\Scripts\python.exe -X utf8 run_qwen_overnight.py --hours 15`，它会另建唯一任务目录。上面的直接run与等待器二选一。

PyCharm请选择现有 `local\qwen_env\Scripts\python.exe`，使用 **Qwen Dialogue V2 Prepare**，查看生成课程后使用 **Qwen Dialogue V2 Train**。已有目录用于恢复；重新开始请改输出目录。

## 明早看什么

先看任务目录的 `job_status.json`、`knowledge/stage_status.json`、`workflow/stage_status.json`，确认是完成、截止保存还是失败。检查失败时留下的 `failure.json` 和最后完整checkpoint，不把“有adapter目录”直接当成成功。

完成后会在同一批12个固定验证来源/事件上，用相同提示比较基础模型和新适配器，保留 `development_evaluation/paired_answers.jsonl` 与汇总。这是开发验证，不使用测试集选检查点。严格分别记录JSON/引用格式、是否又输出固定摘要、是否截断；字面相似度不等于专业正确。逐题看是否正面回答、条件是否丢失、取用是否错位、原文是否支持，才能判断是否值得保留新适配器。不能只凭更低验证loss说能力增强。

还可使用任务目录试问：

```bat
local\qwen_env\Scripts\python.exe -X utf8 run_qwen_curriculum.py ask --job local\qwen_curriculum_v2\run1 --question "天芮星和天心星在疾病判断中有什么区别？"
```
