# WenguaApp — 历史古籍案例“整案一次断词”及书内验证协议

> **强制项目规则（2026-10-19，由用户明确指定）**。适用于今后《神奇之门》《开悟之门》及后来逐本新增的所有预测专题案例，也追溯适用于已保存的6个疾病案例。每章处理时先读本文件和 AGENTS.md。

## 一案、一时、一盘、一解（用户指定的产品协议）

1. **一个问事事件 = 一个不可拆分的 case/event_family**：以原书实际用于断案的时辰、起局方法、完整九宫文字及作者全套取用分析为核心，把用神选择、依据组合、作者最终判断和所有反馈存入同一事件。作者分几次说话或求测人后来补充，不产生另外一张盘、另外一个独立预测任务、或“第二轮重新回答”的产品流程。
2. **WenguaApp V1 面向用户只给一次完整断词**：从最初问事领域/和当事人的关系及当下排盘中一次整理主次用神→本宫及跨宫证据→不同原书格局的相互制约→应期（有来源条件时）→作者式语言结构→最终一句总结；不设计逐回合聊天生成下一版答案。若当前上下文不足，标注未知或保留条件，不擅造事实。
3. **本书学习标签以作者原书为准，默认“书内判对”**：凡书中断语和反馈基本吻合、作者未明说“断错”“修正”“改断”“复盘指出错误”，该独立事件标为 `book_outcome_label=author_book_success_default`；后来补充的资料一律归入同一案的 `validation_information`，作为支持作者判断的**书内印证**。只要书中明确纠错、更正或复盘承认错，标 `author_book_error_explicit` 并保留原推断、更正及错误原因；不能因为模型认为有冲突就静默覆盖原书或推翻用户预设的书内标签。
4. 反馈、后来补充、问答往返的**来源原文和出现时间可保留用于研究溯源**，但不因出现于后段就拆成“新的训练案例”或让 V1 必须多轮交互才能给答案。**分析证据应和后验验证资料分栏**，方便整理作者怎样做出最初判断；最后归属仍是同一整案。训练/评估时同一家族不许跨 train/test 泄漏。
5. **标签的范围边界**：`author_book_success_default` 意味“依书中叙述按作者断对处理”，**不是**“医疗、历史、科学或真实未来事件已有独立验证”，不能伪称独立准确率100%；数据库分别保存 `book_outcome_label` 和 `independent_external_verification`。这是来源忠实与客观验证两个不同维度，不互相否定。
6. **多时辰或多盘的罕见章节**：若原文确实对同一事件不同日期重新起盘，各盘必须独立标识各自时辰并和该事件家族关联；不把1997年没有公开的盘伪造出来，也不能将不同时间的盘混为“一张盘”。仅有一个完整盘时以该盘为唯一可验证排盘对象，其他信息列上下文。
7. **版权来源的永久分离**：公开仓库只存本规范、抽象索引、原文字节SHA、处理代码、测试和适量源行号；整章原文及私人人名谈话在用户私有 SQLite/本地TXT保存。**任何自动导入都不得覆盖历史案例原文。**
8. **领域层知识学习**：每章先记录该领域一般取用规则、人物关系分支、证据先后/反证、应期和作者措辞框架，再逐案保留该规则在特定宫位如何被实际使用。不能拿一例的“个子高矮、外遇、死亡”等标签推广为任意局必然成立的事实或建议。包括关系的象征性断法均需保持“传统术数来源解释”的限定。
9. **每章强制交接**：更新根目录 `AGENTS.md`、`docs/PROJECT_STATUS.md`、`docs/CHAPTER_LEDGER.md`、具体章节 manifest 与完整案例索引、代码及测试；核对公开 GitHub 实际 HEAD SHA，逐一读取所有更新文件，并确认 HEAD 的 CI 真正成功。不能只声称上传。
